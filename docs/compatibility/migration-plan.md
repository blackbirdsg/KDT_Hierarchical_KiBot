# Migration and validation actions

These are future implementation actions, not completed checks. Work on copies until the pipeline is qualified. They do not authorize further Nano design iterations or manufacturing submission.

1. **Establish the environment.** Start an available Docker engine and run the limited environment probe. Record the actual KiCad, KiBot and supporting tool versions. Confirm the digest-pinned image and choose a KiCad patch version containing required fixes; avoid assuming the local 10.0.3 matches the image. Record any changed image digest.
2. **Create a populated fixture.** Include hierarchical sheets, empty/nonempty sheet titles, all named documentation groups/layers, front/back components, DNP parts, mixed SMT/THT, vias, zones, connector models, board cutouts and inner copper layers. Hash inputs and work in a disposable copy. Keep expected output names and content counts in a manifest.
3. **Test template semantics.** Verify XML sheet/title extraction and all project text variables. Keep KiBoM variants initially. Compare fitted/DNP parts across schematic, BOM, assembly PDF, 3D and positions. Check notes/README generation ordering. Confirm stackup/table drawing does not remove or move unrelated groups.
4. **Test every output family.** Run DRAFT, PRELIMINARY and CHECKED locally without publishing. Enable suppressed compatibility warnings during this assessment. Inspect schematic/assembly/fabrication PDFs visually, including custom layers and fonts. Check model availability and 3D camera/crop/transparency. Verify ODB++ actually appears through the KiCad 10 group.
5. **Add an independent release gate.** Refill zones and require clean ERC, schematic-to-PCB parity, DRC and connectivity before creating a manufacturing archive. Document intentional exceptions individually. Delete or isolate stale outputs before each run. Verify deliberately broken fixtures fail and produce no releasable ZIP; `dont_stop: true` is inadequate for this gate.
6. **Qualify fabrication data.** Select the actual PCBWay layer count, copper, thickness and fabrication process. Check trace/space, via/hole sizes, annular rings, copper-to-edge, mask slivers, silk clearances, slots and outline against current manufacturer capabilities. Inspect Gerbers and drills in an independent viewer: layer order/count, closed outline, PTH/NPTH separation, slot format, drill registration, copper pours, solder mask and polarity. Ensure the exported data corresponds to the final hashed board.
7. **Qualify assembly and hand soldering.** Compare BOM quantities/MPNs and fitted parts to the board. Check polarity/pin 1 and readable assembly drawings, USB-C solder access, package land patterns and connector mechanical dimensions. For external assembly, independently verify placement rotations and bottom-side conventions. Provide hand-solder sequence and power-up checks for the actual board.
8. **Adapt CI last.** Add explicit KiCad 10 execution using the tested environment. Fail on unsupported versions and missing output families. Separate report generation from publication. Disable automatic commits, tag rewriting, releases and broad merge-conflict resolution during qualification. Run manual artifact-only CI first and compare with local outputs.
9. **Document acceptance.** Record input hash, tool/image versions, checks, output manifest/hashes and known exceptions. A user-visible release label becomes valid only after its criteria are satisfied. Uploads and orders require separate authorization.

For the Nano, retain its existing four-layer rules and status. Its remaining routing issues are not resolved by adopting this framework. Transfer only selected metadata/output conventions after the tool has passed the populated-fixture checks.
